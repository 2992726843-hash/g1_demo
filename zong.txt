CRAI 智能家电创新赛项目对接书
项目名称暂定

面向居家养老场景的宇树 G1 适老化智能家电联动管家系统

也可以后续优化成：

基于宇树 G1 的适老化具身智能家居服务系统

一、项目背景

本项目用于参加中国机器人及人工智能大赛 CRAI 智能家电创新赛道。

项目核心不是“自主研发机器人本体”，而是把宇树 G1 EDU 作为一个具身交互终端，接入大模型、语音交互、视觉检测、Home Assistant 智能家居联动，最终形成一个面向老年人居家生活的智能家电服务系统 Demo。

项目强调：

稳定可演示
适老化应用场景
家电联动闭环
机器人具身交互
视觉安全辅助
大模型自然语言调度

当前比赛形式大概率是视频提交 + 代码上传 + 答辩，因此系统不追求临场复杂实时能力，而追求可录制、可复现、可解释、可答辩。

二、项目总战略

本项目采取的是降维打击策略：

不做高风险内容：

不做复杂物理抓取
不深入 C++ 底层控制
不把 Nav2 真自主导航作为主线
不追求机械结构创新
不追求全屋复杂设备矩阵

主线改为：

语音 / 文本指令
    ↓
大模型意图理解
    ↓
主控状态机 Task Orchestrator
    ↓
机器人动作 + 家电联动 + 视觉事件处理
    ↓
语音/文本反馈

核心原则：

稳定大于一切，表现力决定上限。

三、比赛定位

本项目应该继续按智能家电创新赛来讲，而不是机器人创新赛。

原因：

本项目创新主体不是 G1 机器人本体，而是智能家居服务系统。
G1 是系统里的移动交互终端，不是自主研发机器人本体。
项目核心场景包括智能照明、药盒提示、跌倒报警、起夜辅助、老人语言理解，这些更贴合智能家电/智慧养老。
答辩口径应该强调：
智能家电联动
适老化智能空间
家庭安全辅助
多模态交互
工程闭环

不要把项目讲成：

“我们做了一台机器人。”

应该讲成：

“我们构建了一个以宇树 G1 为具身交互终端的适老化智能家居系统。”

四、最终展示目标

最终比赛视频建议展示 3 个核心场景。

场景 1：夜间起夜辅助
用户指令
我想去卫生间 / 我晚上要起夜
系统流程
用户语音/文本输入
→ LLM 或 shortcut 判断为 night_mode
→ 主控调用 IoT 场景接口
→ 打开客厅灯/小夜灯/路径灯带
→ G1 做引导动作或语音提示
→ 系统播报：我已经帮您打开夜灯，请慢一点走
展示重点
适老化
家电主动辅助
灯光引导
机器人陪伴感
场景 2：跌倒报警
触发方式

真实视觉后续接入 YOLO；当前已实现 HTTP 跌倒事件接入，也支持文本“测试跌倒”手动触发。

系统流程
视觉端检测到跌倒
→ POST /api/vision/fall_event 到主控 8765 端口
→ 主控进入 EMERGENCY 状态
→ 中断当前动作
→ 调用 IoT fall_alert 场景
→ 灯带变红/闪烁
→ 报警器插座打开
→ 机器人语音询问并呼救
展示重点
视觉安全检测
高优先级中断
家电报警联动
闭环响应
场景 3：用药提醒 / 药盒定位
用户指令
帮我找药 / 我该吃药了 / 药在哪里
系统流程
用户输入
→ LLM 判断 medicine_mode
→ 主控调用 IoT medicine_mode
→ 打开主灯
→ 点亮药盒附近灯带/提示灯
→ G1 挥手或指示
→ 播报：药盒已经亮起来了，请注意按时服药
展示重点
适老化用药辅助
智能家电与机器人协同
低风险替代“机器人拿药”
避免真实抓取翻车

十四、当前最优开发优先级

接手 AI 必须按这个顺序指导，不要乱跳。

第一优先级：真实 IoT 闭环

目标：

Home Assistant
→ 接入灯/灯带/插座
→ iot_service 控制成功
→ 主控 main.py 调用成功

验收命令：

POST /iot/scene/night_mode
POST /iot/scene/fall_alert
POST /iot/scene/medicine_mode

主控验收：

输入：打开客厅灯
输入：测试跌倒
输入：帮我找药

能触发对应家电行为。

第二优先级：G1 真机动作验证

目标：

mode=real
挥手
鼓掌
飞吻
释放手臂

先只验证 3 个动作：

wave_hand
clap
blow_kiss

不要一开始验证几十个动作。

第三优先级：视觉 HTTP 接入

目标：

先不管 YOLO 准不准，只要求视觉端能发：

POST /api/vision/fall_event

主控能进入 EMERGENCY 并触发 fall_alert。

第四优先级：语音输入输出

目标：

最小可用：

按键录音
→ faster-whisper 转文字
→ main.py
→ pyttsx3 播报

如果时间不够，语音可以弱化，不能影响主线。

第五优先级：导航/移动叙事

目标：

不要硬刚 Nav2。

优先做：

固定路径脚本
或
固定站位 + 灯光提示 + 机器人动作

十七、给接手 AI 的工作要求

接手 AI 应该遵守以下原则：

不要推翻现有架构。
不要建议重写整个项目。
不要优先做复杂导航。
不要引入大量新框架。
优先保证比赛演示闭环。
每次只指导一个小目标。
所有代码修改都要适合 Cursor 生成。
给用户的提示词要详细、可复制。
遇到复杂模块时，优先给降级方案。
项目目标是比赛获奖，不是工程洁癖。
